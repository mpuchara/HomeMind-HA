# HomeMind Adaptive AI 0.14.153

Zrzut z 0.14.152 pokazuje około 35,7 s zatrzymania obserwacji Shadow i około 27,5 s zapisu oraz błędy `database is locked` w housekeeping, ocenie sensorów i workerze kandydatów. W logu `adaptive-ai-runtime-debug-20261009-105357.json` starsze wpisy zostały już nadpisane: 3077 utraconych wpisów, zachowany fragment od 08:52:54 do 08:53:55 UTC bez takich długich operacji. Nie można przypisać całego zatrzymania konkretnemu właścicielowi transakcji. Końcowy fragment jest szybszy, lecz screenshot potwierdza, że problem nadal występuje.

Kod pokazał konkretną zależność: domyślny 30-sekundowy busy timeout SQLite działał także podczas zapisu w tle z zajętą blokadą Store, a odczyt metadanych z RAM potrzebował tej samej blokady. SQLite WAL dopuszcza jednego writera, a busy timeout określa oczekiwanie na blokadę ([dokumentacja WAL](https://www.sqlite.org/wal.html), [busy_timeout](https://www.sqlite.org/pragma.html#pragma_busy_timeout)). To uzasadnia ograniczenie oczekiwania dla odtwarzalnych partii; nie dowodzi, która operacja spowodowała wcześniejsze 35 sekund.

## Zmiany

- Okresowe zapisy obserwacji kontekstu i modeli Shadow, housekeeping, provenance, journal cech, fast-light oraz usuwanie wygasłych kopii generacji mają busy timeout 250 ms. Ustawienie jest lokalne dla wątku i zakresu, nie jest globalną zmianą konfiguracji SQLite. Dotychczasowe bufory odtwarzają partię po błędzie; nowszy skumulowany snapshot nadal wygrywa. Sprzątanie zostaje ponowione w kolejnym obiegu.
- Opcjonalna ocena Shadow po decyzji championa korzysta z krótkiego timeoutu. Zajęta baza może spowodować pominięcie tej oceny; błąd jest raportowany i ślad ma status error. Autorytatywne wykonanie decyzji, zapisy kwalifikacji przed oddaniem kontroli, promocje i jawne bariery trwałości zachowują transakcje i wymagane potwierdzenia. Błąd transakcji nie staje się udaną kwalifikacją. Worker treningu poza tym zakresem nadal ma timeout 60 s, zwykłe trwałe operacje 30 s. Końcowe flush przy zamknięciu oraz wywołania jawne pozostają poza krótkim zakresem.
- Automatyczny zapis diagnostyki, także w reakcji na błąd writera, ma ten sam krótki timeout. Błąd bazy nie powoduje kolejnego 30-sekundowego oczekiwania przy raportowaniu; komunikat pozostaje w RAM, a partia wraca do kolejki. Jawny końcowy flush nadal czeka według zwykłej polityki.
- Osobna krótka blokada chroni cache metadanych. Odczyt z RAM nie czeka na zapis na dysk, a cache zmienia się dopiero po udanym commit. Bootstrap aktualizuje cache pod tą samą blokadą.
- Runtime Debug ma osobną ograniczoną historię ostatnich 64 operacji zakończonych błędem lub trwających co najmniej 2 s. Pozostają po nadpisaniu zwykłego pierścienia 4096 wpisów; mają początek, czas, wątek i pola operacji. Zatrzymanie debug zachowuje także nadal aktywne długie operacje ze statusem `tracing_stopped`. Clear usuwa obie historie.
- Ślady `sqlite_transaction` obejmują przygotowanie połączenia, blok transakcji i commit; pokazują miejsce wywołania, timeout, wersję SQLite i kod błędu. Nie zapisują SQL ani parametrów. Bez debug instrumentacja nie tworzy śladów. Reużyta sesja nie jest przedstawiana jako wielominutowa transakcja; zwykłe odczyty z sesji nie dodają zapytań o timeout w każdym przebiegu. Błąd przygotowania PRAGMA również zamyka fizyczne połączenie.

## Sprawdzenie i ograniczenia

17 nowych regresji obejmuje rzeczywistą zewnętrzną blokadę WAL, krótkie oczekiwanie i retry najnowszej partii, niezależność wątków i zagnieżdżonych zakresów, przywrócenie timeoutu po rollback w reużytym połączeniu, cache po commit i po błędzie, odczyt RAM przy zajętym Store, jawny flush czekający dłużej niż 250 ms, politykę okresowego i końcowego flush rzeczywistego writera Shadow, krótkie raportowanie błędu przy zajętej bazie, zamykanie połączenia po nieudanym przygotowaniu, kody SQLite i miejsce wywołania oraz zachowanie, ograniczenie i czyszczenie ważnych śladów. Pełny zestaw: 1790 testów. CI sprawdza dodatkowo obsługiwane wersje Pythona i obraz dodatku.

250 ms ogranicza oczekiwanie SQLite na blokadę, a nie czas całej operacji: kolejka na Store, wolna karta, commit lub kilka transakcji mogą trwać dłużej. Część operacji wymagających trwałego zapisu nadal może czekać. Trwała niedostępność bazy wydłuża zaległości, a nagła utrata zasilania może utracić niezapisane obserwacje. Ta wersja nie dowodzi przewagi jakości agenta nad automatyzacją ani usunięcia wszystkich opóźnień; nowy ślad powinien umożliwić ustalenie miejsca pozostałych zatrzymań. Schemat modeli i rewizja treningu pozostają zgodne, krótkie poprawne wizyty nadal są uczone.

## Instalacja

Zaktualizuj dodatek do 0.14.153 i zrestartuj. Rebuild nie jest potrzebny. ZIP ręcznej instalacji: `HomeMind-Adaptive-AI-0.14.153-addon-root.zip`; publiczne sumy SHA256 są obok pakietów. Po odtworzeniu scenariusza włącz Runtime Debug i pobierz JSON; pole `critical_spans` zachowa wcześniejsze długie operacje nawet po nadpisaniu zwykłych wpisów (do limitu 64).
